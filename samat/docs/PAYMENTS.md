# الدفع — SAMAT

## المبدأ

- السعر النهائي يُحسب في قاعدة البيانات (`place_order`) — لا يُقبل أي سعر من المتصفح.
- الطلب يُنشأ بحالة **بانتظار الدفع** ويحجز المخزون لمدة `unpaid_order_ttl_minutes` (افتراضياً ٢٠ دقيقة).
- بعد الدفع/رفع الإيصال يصير **بانتظار موافقة المطعم** — ولا يصل للمطبخ قبل موافقتك.
- لا تُخزَّن بيانات البطاقات في نظام المطعم أبداً.

## 1) التحويل البنكي مع رفع الإيصال (مفعّل)

**تجربة العميل:** صفحة الدفع تعرض اسم المستفيد، الآيبان (مع زر نسخ)، رقم الحساب، رمز QR الخاص بالتحويل، والمبلغ المطلوب بالضبط. العميل يحوّل من تطبيق البنك ثم يرفع صورة الإيصال (JPG/PNG/HEIC/PDF حتى ٨ ميجا).

**الأمان:**
- نوع الملف يُفحص من محتواه (وليس من الامتداد).
- الإيصال يُحفظ في مخزن **خاص** (`receipts`) ولا يظهر إلا للموظف عبر رابط مؤقت مدته ١٠ دقائق.

**تجربة الإدارة:** الطلب يظهر بحالة "تحويل بانتظار التحقق" مع صورة الإيصال.
- زر **قبول الطلب** يبقى معطل حتى تضع علامة "تأكدت إن المبلغ وصل حساب المطعم" — تحقق من تطبيق البنك أولاً.
- عند **الرفض**: إذا وصل المبلغ، علّم "المبلغ وصل الحساب" ← تصير الحالة "استرجاع قيد المعالجة". حوّل المبلغ للعميل من تطبيق البنك ثم اضغط **تم الاسترجاع يدوياً**. وإذا ما وصل المبلغ، يُسجل الدفع كفاشل ولا يلزم استرجاع.

**الإعداد:** الإعدادات ← وسائل الدفع ← "تحويل بنكي مع رفع الإيصال"، ثم عبّئ بيانات الحساب وارفع صورة QR.
بيانات البنك محفوظة في قاعدة البيانات فقط، وليست في الكود.

## 2) ميسّر Moyasar (جاهز — يحتاج مفاتيح حسابك)

| الخطوة | التفاصيل |
|---|---|
| المفاتيح | Dashboard → Settings → API Keys: `pk_test_…` / `sk_test_…` أولاً، ثم live |
| المتغيرات | `PAYMENT_PROVIDER=moyasar`, `NEXT_PUBLIC_MOYASAR_PUBLISHABLE_KEY`, `MOYASAR_SECRET_KEY` |
| Webhook | Dashboard → Webhooks → URL: `https://<موقعك>/api/webhooks/moyasar`، Secret token: نفس قيمة `MOYASAR_WEBHOOK_SECRET`، الأحداث: paid, failed, authorized, captured, voided, refunded |
| الوسائل | فعّل في **الإعدادات** فقط الوسائل المفعلة فعلاً في حسابك (مدى/فيزا/ماستركارد، Apple Pay، STC Pay) |
| Apple Pay | سجّل الدومين لدى ميسّر (ملف التحقق) قبل التفعيل |

**التدفق المنفذ:**
1. نموذج ميسّر الرسمي (`cdn.moyasar.com/mpf/1.16.0`) ينشئ الدفعة من المتصفح مع `metadata` (رقم الطلب ورقم سجل الدفع).
2. الخادم **يجلب الدفعة من API ميسّر** ويتحقق من: المبلغ = إجمالي الطلب، العملة SAR، وأن الدفعة تخص هذا الطلب. لا يثق بالرابط ولا بجسم الـ Webhook.
3. **تفويض ثم تحصيل** (`manual_capture` مفعّل افتراضياً): يُحجز المبلغ، وعند ضغط "قبول" يُحصَّل (capture)، وعند "الرفض" يُلغى التفويض (void) فلا يُخصم من العميل أصلاً.
4. إذا كانت الدفعة محصّلة مسبقاً يتم **الاسترجاع** (refund) عند الرفض أو الإلغاء.
5. حالة "تم الاسترجاع" تظهر **فقط بعد تأكيد ميسّر**. وإذا فشل الاسترجاع تبقى "قيد المعالجة" ويصلك بريد تنبيه مع زر "إعادة محاولة".

**منع التكرار:**
- مفتاح idempotency لكل عملية checkout.
- الـ Webhook يُسجَّل برقم الحدث مرة واحدة (`payment_events`).
- `mark_order_paid` لا يغيّر الحالة مرتين.
- لكل حدث إشعار واحد فقط لكل قناة.

**حالات خاصة:** إذا وصل الدفع بعد انتهاء المهلة ونفد المخزون، يُسترجع المبلغ تلقائياً. وإذا كان المبلغ المدفوع مختلفاً عن الطلب، تُرفض الدفعة وتُسترجع.

## 3) محاكي الدفع (للتطوير فقط)

`PAYMENT_PROVIDER=simulator` يعرض أزرار "دفع ناجح / تفويض / مرفوض" لاختبار النظام بدون أموال حقيقية.
معرّف الدفعة موقّع بمفتاح الخادم فلا يمكن تزويره، والمسار يرجع **404** تلقائياً عندما `NODE_ENV=production`.

# وارد | WARD — الموقع و WARD OS

**كل شيء وارد.**

هذا المجلد يحتوي على تطبيق Next.js واحد يضم:

| المسار | ما هو |
|---|---|
| `/` | موقع وارد العام (من الملف الإعلامي ودليل الهوية)، بخط **WARD TYPE Original** |
| `/os` | **WARD OS** — غرفة القيادة الخاصة: مؤسس واحد يدير مؤسسة إعلامية بمساعدة تسعة وكلاء ذكاء اصطناعي |
| `/api/os/*` | واجهات WARD OS البرمجية (محمية بالجلسة والصلاحيات) |
| `/api/cron` | مضخة الطابور الدائم للمهام الخلفية (محمية بسر) |

> لم يُعثر على موقع وارد سابق في هذا المستودع أو في حسابات Vercel/Supabase المتصلة، لذلك بُني الموقع العام هنا من محتوى الملف الإعلامي ودليل الهوية. التطبيق مستقل داخل `ward/` ولا يمس مشروع NABD الموجود في بقية المستودع.

## التشغيل محليًا

```sh
cd ward
npm install
cp .env.example .env.local          # ثم ضع WARD_FOUNDER_EMAIL و WARD_FOUNDER_PASSWORD (12 حرفًا+)
npm run dev                          # http://localhost:3100  ·  WARD OS: /os
```

بدون `DATABASE_URL` يستخدم التطبيق Postgres مضمّنًا (PGlite) في `.data/pglite`، ويطبّق الـ migrations والبيانات الأولية تلقائيًا عند أول تشغيل. لن يعمل أي وكيل حتى تضيف مفتاح مزود واحد على الأقل؛ تُظهر الواجهة ذلك بوضوح ولا تختلق أي مخرجات.

| الأمر | الوظيفة |
|---|---|
| `npm run dev` / `build` / `start` | تطوير / بناء إنتاجي / تشغيل إنتاجي |
| `npm run typecheck` · `lint` · `test` | TypeScript · ESLint · Vitest |
| `npm run verify` | الأربعة معًا |
| `npm run db:migrate` · `db:seed` | تطبيق الـ migrations · البيانات الأولية (آمن للتكرار) |
| `npm run founder:create -- --email you@x.com --name "..."` | إنشاء حساب المؤسس |
| `npm run worker` | عامل الخلفية الدائم (للخوادم طويلة التشغيل) |
| `npm run fonts:build` | إعادة توليد الخط من المصدر (يتطلب Python + fonttools/shapely/brotli) |

## خط WARD TYPE Original

- المصدر: `tools/ward-type/build.py` (النسخة 0.1 كما وصلت، **دون أي تعديل** — الاختبار يتحقق من بصمة الملف).
- المخرجات: خمسة أوزان في `public/fonts/` — Light 300 · Regular 400 · Medium 500 · Bold 700 · Black 900 — بصيغتي **WOFF2** و **TTF**. كل وزن: 258 glyph و153 محرفًا، مع GSUB (init/medi/fina/rlig) و GPOS (mark).
- الربط: `src/app/ward-type.css` يعرّف `@font-face` للأوزان الخمسة (WOFF2 أولًا ثم TTF)، ويُستورد في الـ layout الجذري، فيستخدمه الموقع العام و WARD OS معًا. الوزنان Bold و Black محمّلان مسبقًا (`preload`).
- الاستخدام: الخط للعناوين والهوية (`--font-display`)، والنصوص الطويلة بخط IBM Plex Sans Arabic كما ينص دليل الهوية — وتنفيذًا لتنبيه مصدر الخط بعدم استبدال خط النصوص قبل اختبار الواجهات.
- تنبيه من مصدر الخط نفسه: نسخة أولية تحتاج اختبارًا لغويًا وبصريًا أوسع وضبط مسافات؛ لا توجد شهادة قانونية بعدم التشابه.

## WARD OS — ما تم بناؤه

**الوكلاء التسعة** (`src/lib/agents/definitions.ts`): Chief · Editorial · Production · Marketing · Business · Finance · Relations · Tech · Review. لكل وكيل تعليمات مستقلة، وقائمة أدوات بأقل صلاحية (يستطيع المؤسس تقليصها لا توسيعها)، وذاكرة خاصة، وسجل تشغيل، ونموذج/مزود قابل للتغيير، وميزانية يومية اختيارية.

**منسق الوكلاء** (`src/lib/orchestrator`): أمر المؤسس ← تحليل وخطة (DAG مُتحقق منها) ← تنفيذ الخطوات المستقلة بالتوازي ← تمرير مخرجات الخطوات إلى ما يعتمد عليها ← مراجعة وكيل الجودة (جولة تعديل واحدة كحد أقصى) ← تقرير نهائي ← انتظار الموافقة عند الحاجة.
الحالات: `queued · planning · running · reviewing · awaiting_approval · completed · failed · cancelled`. يدعم الإلغاء وإعادة المحاولة والاستئناف (مع رفع سقف التكلفة)، وسجل تنفيذ مفصل.
**لا حلقات لا نهائية:** حد للخطوات، وللمحاولات لكل خطوة، ولدورات الأدوات لكل وكيل (تُسحب الأدوات في الدورة الأخيرة)، ولعدد استدعاءات النموذج وللتكلفة لكل أمر، وجولة مراجعة واحدة.

**بوابة المزودين** (`src/lib/ai`): Anthropic · OpenAI · Gemini · DeepSeek · Ollama بواجهة واحدة — Tool Calling، Structured Outputs (مع تحقق Zod وجولة إصلاح واحدة)، Streaming، قياس tokens، حساب التكلفة، نموذج اقتصادي للمهام البسيطة، إعادة المحاولة مع تراجع، و Fallback بين المزودين المعدّين. **يُفحص سقف الإنفاق قبل كل استدعاء** بأسوأ تقدير (اليومي، الشهري، الأمر، الاجتماع، ميزانية الوكيل، الأتمتة).

**مركز الموافقات**: الأدوات الحساسة الثمانية (النشر، المراسلة الخارجية، الاتفاقيات، الصرف، الحذف، تعديل الموقع، مشاركة الملفات، الصلاحيات) **لا تنفّذ شيئًا** — تنشئ طلبًا يعرض الإجراء والتكلفة والجهة المستهدفة، والقرار للمؤسس وحده. بعد الموافقة يُنفّذ النظام فقط ما يستطيع فعله حقًا (تسجيل مصروف، حذف سجل، تغيير صلاحية، إرسال بريد عبر Resend إن أُعدّ)، وما عدا ذلك يُعلَّم «يدوي» بصراحة.

**غرفة الاجتماعات**: موضوع + وكلاء (2–9) + جولات (1–3). يتحدث كل وكيل من تخصصه ويرد على زملائه، ثم يصدر: الملخص، التوصيات، نقاط الاختلاف، القرارات المقترحة (تنتظر اعتمادك)، والمهام مع المسؤول عن كل منها. كل شيء محفوظ.

**الذاكرة المؤسسية (RAG)**: هوية وارد، الأهداف وخطة 90 يومًا، السياسات، الرعايات، الحلقة الأولى… (مأخوذة من مستنداتك وموثقة). رفع PDF/DOCX/TXT/صور مع استخراج النص وفهرسة بحث نصي عربي (توحيد الهمزات والتاء المربوطة والتشكيل). يعدّل المؤسس ويحذف ويوثّق. المحتوى المرفوع ومخرجات الوكلاء غير موثقة وتُعامل كبيانات غير موثوقة.

**الحلقات**: مسار الحالات العشر، العنوان والضيف والوصف والأسئلة والسيناريو وموعد التصوير والملفات والمهام والرعاة والتكلفة والمحتوى التسويقي وحالة الاعتماد وروابط النشر. **تأكيد الضيف والنشر للمؤسس فقط**، والنشر يتطلب الاعتماد (قيد في قاعدة البيانات أيضًا). الحلقة الأولى «أكبر من عمره» مضافة كمسودة بضيف مقترح غير مؤكد.

**الرعايات**: الشعار، الاسم، الفئة، التواصل، المدة، القيمة، النوع، حقوق الظهور، المستندات، الحالة، الحلقات المرتبطة، التسليمات ومتابعتها، ومسودات الاتفاقيات. العلامات الإحدى عشرة مضافة **بحالة انتظار التحقق، بلا قيم أو تواريخ أو عقود**.

**المهام والتقويم**: Kanban بالسحب والإفلات، قائمة، تقويم شهري (مهام + مواعيد تصوير + تقويم المحتوى)، أولوية، مواعيد، إسناد لوكيل أو مستخدم، مهام فرعية، اعتماديات (مع منع الدوائر ومنع الإنجاز قبل اكتمال الاعتماديات)، مرفقات، تعليقات، وسجل تغييرات.

**الأتمتة** (معطلة كلها افتراضيًا، لكل منها سقف تكلفة): التقرير الصباحي، الأسبوعي، مراجعة مواعيد التصوير، متابعة حقوق الرعاة، اقتراح أفكار حلقات، مراجعة المصاريف، تنبيه المواعيد، مراقبة الأخطاء. تعمل من طابور دائم في Postgres — لا تعتمد على المتصفح.

**مركز القيادة**: حالة الوكلاء، التشغيل الحالي والمكتمل، الموافقات، الحلقات القادمة، جدول التصوير، الرعايات، الميزانية، تكاليف الذكاء الاصطناعي، الأداء، التنبيهات، ومربع أوامر مركزي — كلها من قاعدة البيانات.

## الأمان

- مصادقة بالبريد وكلمة المرور (scrypt)، جلسات مخزّنة كبصمة SHA-256، كوكي `HttpOnly` + `SameSite=Strict` + `__Host-`/`Secure` في الإنتاج.
- تحقق CSRF من الأصل (Origin) لكل طلب يغيّر البيانات، و CSP بـ nonce لكل طلب، و `noindex` لكل `/os`.
- صلاحيات على الخادم (`owner · admin · editor · viewer`)؛ قرارات المؤسس محصورة في `owner`.
- **عزل المؤسسات في قاعدة البيانات نفسها**: كل جدول في مخطط `ward` عليه RLS؛ كل طلب يعمل بدور `ward_app` المقيد داخل معاملة مثبتة على المؤسسة. مخطط `ward` غير مكشوف لـ REST في Supabase، وأدوار `anon/authenticated` محرومة منه.
- سجل تدقيق غير قابل للتعديل من التطبيق، Rate limiting في Postgres (يصمد عبر الخوادم)، تحقق Zod من كل مدخل، فحص نوع الملفات بالبصمة لا بالاسم.
- حماية الوكلاء من Prompt Injection: كل محتوى خارجي يُغلّف كبيانات غير موثوقة ويُوسم إذا بدا مريبًا، الأدوات مقيدة لكل وكيل، والإجراءات الحساسة لا تُنفّذ إلا بموافقة بشرية مهما قال النموذج.
- المفاتيح في متغيرات البيئة على الخادم فقط. **زر إيقاف جميع الوكلاء** في الشريط العلوي.

## الاختبارات

`npm test` يشغّل 62 اختبارًا على Postgres حقيقي (PGlite في الذاكرة) مع جميع الـ migrations:

- العزل بين المؤسسات (RLS)، وجداول الجلسات والحدود المحجوبة، وسجل التدقيق غير القابل للتعديل.
- المنسق: خطة → تنفيذ متوازٍ → تمرير المخرجات → مراجعة → تقرير → انتظار موافقة؛ جولة مراجعة واحدة؛ إعادة المحاولة والإلغاء؛ رفض الخطط غير الصالحة؛ فشل صريح بلا مزود.
- حدود الإنفاق (الأمر، اليومي، الوكيل، الاجتماع) ومنع الحلقات اللانهائية وزر الإيقاف.
- منع النشر دون موافقة (الأداة، الواجهة البرمجية، وقيد قاعدة البيانات) وحصر القرار بالمؤسس.
- صيغ مزودي الذكاء الاصطناعي الخمسة (طلبات وردود و streaming) والـ fallback.
- المصادقة، CSRF، مصفوفة الصلاحيات، الملفات الخاصة، الاسترجاع، الاجتماعات، الأتمتة، cron، والخط.

المزود الوهمي في الاختبارات (`tests/helpers.ts`) يُركّب عبر دالة ترفض العمل في الإنتاج.

## حدود صريحة (ما لم يُنفذ أو يحتاج منك شيئًا)

- **مفاتيح الذكاء الاصطناعي:** لا يوجد أي مفتاح في البيئة؛ لم يُشغَّل أي نموذج حقيقي. أضف مفتاحًا ثم اضغط «اختبار الاتصال» في الإعدادات.
- **الأسعار:** لم تُثبَّت أسعار للنماذج (عدا Ollama = 0)؛ تُحسب بسعر تقديري مرتفع عمدًا حتى تدخل الأسعار الفعلية في الإعدادات. أسماء النماذج الافتراضية قابلة للتغيير.
- **قاعدة البيانات:** لا يوجد مشروع Supabase خاص بوارد، ولم ألمس المشاريع الموجودة (دوري، samat…). الـ migrations جاهزة لأي Postgres/Supabase.
- **النشر والتكاملات الخارجية:** لا نشر تلقائي على يوتيوب/إنستغرام/تيك توك. البريد عبر Resend فقط إن أُعدّ.
- **الصور:** لا OCR؛ تُرفع الصورة مع وصف يكتبه المؤسس. البحث نصي (Full-text) وليس متجهيًا.
- **المصادقة:** حسابات داخلية بالبريد وكلمة المرور، بدون مصادقة ثنائية بعد.

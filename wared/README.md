# وارد — كل شيء وارد.

منصة إعلامية سعودية مستقلة: بودكاست، قصص، حوارات، تجارب إنسانية ومقالات.
هذا المجلد مشروع Next.js مستقل وقابل للنشر، فيه الموقع العام ولوحة تحكم الفريق وقاعدة البيانات واختباراتها.

> **الحالة:** الكود مكتمل ومختبَر محليًا. لم يُربط بعد بمشروع Supabase حقيقي ولا بـVercel ولا بمزود بريد.
> كل خدمة خارجية جاهزة في الكود، وخطوات تفعيلها مشروحة أدناه. الموقع لا يعرض أي حلقات أو ضيوف أو أرقام
> وهمية: بدون قاعدة بيانات تظهر حالات فارغة صادقة، ووضع العرض التجريبي معلَّم بشريط واضح ولا يُفهرس.

## ما الذي بُني

### الموقع العام (عربي RTL أصلي + إنجليزي LTR)

الروابط منظمة بلغتين: `/ar/...` و`/en/...`. الرابط `/` يوجّه حسب لغة المتصفح أو آخر اختيار.

| الصفحة | المسار |
|---|---|
| الرئيسية | `/ar` |
| البودكاست | `/ar/podcast` |
| جميع الحلقات (مع تصفية بالبرنامج) | `/ar/episodes` |
| صفحة الحلقة | `/ar/episodes/[slug]` |
| البرامج / صفحة البرنامج | `/ar/programs`، `/ar/programs/[slug]` |
| القصص والمقالات / المقال | `/ar/stories`، `/ar/stories/[slug]` |
| المقاطع القصيرة | `/ar/clips` |
| الضيوف / صفحة الضيف | `/ar/guests`، `/ar/guests/[slug]` |
| البحث (يشمل النصوص المفرغة) | `/ar/search` |
| عن وارد، انضم إلى الفريق، الرعاية والإعلانات، تواصل معنا | `/ar/about`، `/ar/join`، `/ar/sponsorship`، `/ar/contact` |
| سياسة الخصوصية، شروط الاستخدام | `/ar/privacy`، `/ar/terms` |
| تأكيد وإلغاء النشرة | `/ar/newsletter/confirm`، `/ar/newsletter/unsubscribe` |
| 404 مخصصة، صفحة بدون اتصال (PWA) | أي رابط غير موجود، `/ar/offline` |

### مشغل الحلقات

- تشغيل وإيقاف، تقديم ورجوع 15 ثانية، سرعات 0.75–2×، مستوى الصوت والكتم، شريط تقدم يمكن التحكم فيه بلوحة المفاتيح.
- **يستمر التشغيل أثناء التنقل** بين الصفحات (المشغل في الـlayout، ومشغل مصغّر ثابت أسفل الشاشة).
- **حفظ موضع الاستماع** في المتصفح، ومزامنته مع قاعدة البيانات بمعرّف مستمع مجهول، واستعادة المشغل بعد إعادة التحميل.
- **فصول الحلقة** (النقر للانتقال، وإبراز الفصل الحالي)، و**النص المفرغ** مع البحث داخله وتتبع التشغيل.
- **مشاركة لحظة محددة**: رابط `?t=ثواني` يفتح الحلقة على تلك اللحظة.
- **Media Session API**: التحكم من شاشة القفل والسماعات والسيارة، وأزرار السابق/التالي تتنقل بين الفصول.
- تكامل **YouTube** (يُحمَّل بعد ضغطة المستخدم وبنطاق youtube-nocookie)، و**Spotify** و**Apple Podcasts** عبر التضمينات الرسمية.

### لوحة التحكم `/admin`

تسجيل دخول آمن، ونسيت كلمة المرور، ودعوات الفريق بالبريد. وتشمل:

- **المحتوى**: الحلقات (مع رفع الصوت، والفصول، والنص المفرغ بصيغ نص عادي أو WebVTT أو SRT، والضيوف)، والبرامج، والمقالات، والضيوف، والمقاطع القصيرة، والتصنيفات.
- **النشر**: مسودة، ثم مراجعة، ثم منشور أو مجدول. المجدول يظهر للجمهور تلقائيًا في موعده دون أي مهمة مجدولة، لأن سياسات قاعدة البيانات نفسها تقارن بوقت النشر.
- **مكتبة الوسائط**: رفع مباشر من المتصفح إلى Supabase Storage مع شريط تقدّم، وفحص نوع الملف من محتواه الفعلي، ونص بديل للصور.
- **المعاينة** قبل النشر بنفس شكل الموقع ومشغله.
- **الجمهور**: رسائل التواصل، وطلبات الرعاية (بحالات ومتابعة وملاحظات داخلية)، ومشتركو النشرة مع تصدير CSV.
- **الإحصائيات الفعلية**: مشاهدات الصفحات، ومرات التشغيل، والمستمعون، ونسبة الإكمال، والحلقات الأكثر تشغيلًا، والمصادر، والأجهزة. كلها من أداة داخلية بدون أطراف ثالثة.
- **المستخدمون والصلاحيات** بأربعة أدوار، و**إعدادات الموقع والهوية**، و**سجل العمليات** لكل تغيير.

## التشغيل محليًا

المتطلبات: Node.js 20.9 أو أحدث (مختبَر على 22).

```bash
cd wared
npm install
cp .env.example .env.local     # ثم عبّئ القيم
npm run dev                     # http://localhost:3000
```

**معاينة التصميم بدون قاعدة بيانات:** ضع `NEXT_PUBLIC_DEMO_CONTENT=1` في `.env.local`.
يظهر محتوى تجريبي معلَّم بشريط أعلى كل صفحة، وصوت التيزر لتجربة المشغل. الصفحات في هذا الوضع لا تُفهرس.
**لا تفعّله في الإنتاج.**

**بدون أي متغيرات:** الموقع يعمل ويعرض حالات فارغة صادقة («الحلقة الأولى في الطريق»)، والنماذج ترد بأنها غير متاحة.

## إعداد Supabase

### 1. إنشاء المشروع وتطبيق قاعدة البيانات

أنشئ مشروعًا في [supabase.com](https://supabase.com)، ويُفضل اختيار منطقة قريبة من السعودية. ثم:

```bash
cd wared
npx supabase login
npx supabase init            # مرة واحدة: ينشئ config.toml ويُبقي مجلد migrations كما هو
npx supabase link --project-ref <PROJECT_REF>
npx supabase db push         # يطبّق كل ملفات supabase/migrations بالترتيب
```

أو الصق محتوى الملفات الثلاثة في `supabase/migrations` بالترتيب داخل SQL Editor.

ما تنشئه الـmigrations:

- 19 جدولًا مطلوبًا، مع جدول إضافي هو `rate_limits` لتحديد معدل الطلبات. لكل جدول علاقاته وفهارسه وقيوده.
- سياسات **Row Level Security** لكل جدول، والأدوار الأربعة وصلاحياتها.
- trigger لسجل العمليات، وآخر لإنشاء الملف الشخصي لكل حساب جديد.
- دوال البحث العربي (توحيد الهمزات والتاء المربوطة والألف المقصورة وحذف التشكيل)، ودالة الإحصائيات، ودالة تحديد المعدل.
- ثلاث حاويات تخزين (`images`، `audio`، `video`) بحدود الحجم والأنواع المسموحة.

### 2. المفاتيح

من Project Settings → API انسخ:

- Project URL إلى `NEXT_PUBLIC_SUPABASE_URL`
- المفتاح العام (publishable، أو anon في المشاريع القديمة) إلى `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- المفتاح السري (secret، أو service_role في المشاريع القديمة) إلى `SUPABASE_SECRET_KEY`، **على الخادم فقط**

### 3. إعداد المصادقة (Authentication)

- **Sign In / Providers → Email:** أوقف «Allow new users to sign up». الدخول للفريق بالدعوة فقط.
- **URL Configuration:** اضبط Site URL على رابط موقعك، وأضف `https://YOUR-DOMAIN/admin/auth/confirm` إلى Redirect URLs.
- **Email Templates:** عدّل رابطي «Invite user» و«Reset password» ليستخدما مسار التأكيد في الموقع:

  ```
  Invite:  {{ .SiteURL }}/admin/auth/confirm?token_hash={{ .TokenHash }}&type=invite&next=/admin/account
  Reset:   {{ .SiteURL }}/admin/auth/confirm?token_hash={{ .TokenHash }}&type=recovery&next=/admin/account
  ```

- **SMTP:** يُنصح بربط مزود بريد (مثل Resend) في Auth → SMTP Settings، لأن بريد Supabase الافتراضي محدود جدًا.

### 4. التخزين

ارفع «Upload file size limit» العام في Storage Settings إلى 500MB على الأقل، لأن ملفات الحلقات الصوتية كبيرة.
الحاويات نفسها تحدّ الصوت بـ500MB والفيديو بـ300MB والصور بـ10MB.

### 5. أول مالك

1. Authentication → Users → **Invite user** (أو Add user بكلمة مرور).
2. شغّل `supabase/bootstrap-owner.sql` في SQL Editor بعد تعديل البريد.
3. ادخل `/admin` وادعُ بقية الفريق من صفحة «المستخدمون والصلاحيات».

## النشر على Vercel

1. Import المستودع في Vercel، واجعل **Root Directory = `wared`**. يكتشف Vercel إطار Next.js تلقائيًا.
2. Environment Variables: كل ما في `.env.example`، وحدّث `NEXT_PUBLIC_SITE_URL` لرابط النطاق النهائي.
3. اربط النطاق. يُفعَّل ترويسة HSTS وترقية الطلبات إلى HTTPS تلقائيًا متى كان الرابط يبدأ بـ`https://`.
4. بعد النشر: أرسل `https://YOUR-DOMAIN/sitemap.xml` إلى Google Search Console.

ملاحظات تشغيلية:

- الصفحات العامة ثابتة تتجدد كل 60 ثانية، وتتحدث فورًا عند الحفظ من لوحة التحكم.
- لوحة التحكم تُعرض لكل طلب ولا تُخزَّن في الكاش.
- رفع الملفات يتم من المتصفح مباشرة إلى Supabase، فلا يصطدم بحد حجم الطلب في Vercel.

## البريد الإلكتروني

عبر [Resend](https://resend.com):

1. وثّق نطاق الإرسال.
2. أضف `RESEND_API_KEY` و`EMAIL_FROM`.
3. أضف `INBOX_NOTIFY_EMAIL` لتنبيه الفريق بالرسائل الجديدة.

ما يحدث بدون بريد مفعّل: تُحفظ اشتراكات النشرة «بانتظار التأكيد»، ويُقال للمشترك ذلك بصدق، ولا تصل تنبيهات للفريق.

> هذا المشروع يرسل **رسائل التأكيد** فقط. إرسال أعداد النشرة نفسها يحتاج أداة Broadcasts أو أداة نشرات منفصلة،
> وتصدير المشتركين (CSV) متاح من لوحة التحكم.

## منصات البودكاست وRSS

- خلاصة كل البرامج: `/rss.xml`. خلاصة كل برنامج: `/rss/<slug>`. **أرسل خلاصة البرنامج إلى Apple Podcasts وSpotify وغيرهما.**
- متوافقة مع itunes وPodcasting 2.0: الفصول بصيغة JSON على `/api/episodes/<slug>/chapters`، والنص المفرغ بصيغة WebVTT على `/api/episodes/<slug>/transcript`.
- قبل الإرسال لآبل أضف «بريد التواصل العام» في إعدادات الموقع (يظهر في `itunes:owner`)، وارفع غلافًا مربعًا للبرنامج بين 1400 و3000 بكسل.
  إن لم يُرفع غلاف تُستخدم `public/brand/podcast-artwork.jpg` (3000×3000).
- لا تظهر في الخلاصة إلا الحلقات المنشورة التي لها ملف صوتي.
- بعد قبول البرنامج في المنصات، أضف روابطه في «إعدادات الموقع». **الموقع لا يعرض رابط منصة غير مضاف.**

## الصلاحيات والأمان

| الدور | الصلاحيات |
|---|---|
| المالك | كل شيء، بما فيه إدارة المالكين |
| المدير | كل شيء عدا منح دوري المالك والمدير |
| المحرر | إنشاء كل المحتوى وتعديله ونشره وجدولته وحذفه، والوسائط، والإحصائيات |
| الكاتب | كتابة مسودات المقالات الخاصة به وإرسالها للمراجعة، ورفع الملفات |

الأدوار مطبّقة **في قاعدة البيانات** (RLS)، لا في الواجهة فقط. وتمنع trigger:

- أن يغيّر أي شخص دوره بنفسه.
- أن يمنح المدير دورًا يساوي دوره أو يعلوه.
- إزالة آخر مالك.

إجراءات الحماية الأخرى:

- **حماية لوحة التحكم على الخادم:** طبقة `proxy.ts` تحوّل غير المسجلين، ثم كل صفحة وكل إجراء يتحقق من المستخدم عبر Supabase Auth ومن صلاحيته.
- **لا تتلقى قاعدة البيانات أي إدخال مباشر من الزوار.** النماذج والإحصائيات تمر عبر الخادم بعد فحصها، فلا يمكن استخدام المفتاح العام لتجاوز الحماية.
- **التحقق من المدخلات** بـZod في المتصفح ثم مرة ثانية في الخادم، وقيود CHECK في قاعدة البيانات.
- **Rate limiting** عبر دالة في قاعدة البيانات، فيعمل عبر كل نسخ الخادم على Vercel. يشمل النماذج، وتسجيل الدخول لكل IP ولكل حساب، والإحصائيات.
- **حماية النماذج:** حقل فخ مخفي، ورمز زمني موقّع يرفض الإرسال الآلي الفوري، وحماية CSRF المدمجة في Server Actions، وفحص Origin في مسارات API.
- **حماية رفع الملفات:**
  - روابط رفع موقّعة قصيرة العمر تصدر بعد فحص الصلاحية.
  - قائمة أنواع وحدود حجم في الخادم وفي الحاويات.
  - **فحص البايتات الأولى من الملف المخزَّن** ورفضه وحذفه إن لم يطابق نوعه المعلن.
- **الأسرار:** المفتاح السري وAPP_SECRET في وحدات `server-only` فقط.
- **عناوين IP لا تُحفظ إطلاقًا.** تُجزّأ بمفتاح سري لتحديد المعدل فقط، وتُحذف خلال يوم.
- **ترويسات الأمان:** CSP، وHSTS، وX-Frame-Options، وReferrer-Policy، وPermissions-Policy.
- **النصوص الغنية:** تُحوَّل لعناصر React بدون HTML خام، فلا يمكن حقن سكربت من محتوى المحررين.

ملاحظة: الملفان `SECURITY.md` و`THREAT-MODEL.md` في جذر المستودع يخصان مشروع NABD الآخر، لا وارد.

- مسار تسجيل الدخول الفعلي، ورفع ملف فعلي إلى Storage، وإرسال البريد.
- هذه المسارات مكتوبة على واجهات Supabase وResend الموثقة.
- سياسات قاعدة البيانات نفسها مختبرة على PostgreSQL.

جرّبها بعد الربط بالخطوات التالية:

1. ادخل بحساب المالك.
2. أنشئ برنامجًا، ثم حلقة مع ملف صوتي، وانشرها.
3. افتح `/rss/<slug>`.
4. اشترك في النشرة.
5. أرسل رسالة من صفحة التواصل وتأكد من وصولها للوحة التحكم.

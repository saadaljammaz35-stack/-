# رفع «ضَمان» على App Store

دليل من الصفر إلى **Submit for Review**. **لا تحتاج جهاز ماك** — البناء يتم في سحابة
Expo (EAS). كل أمر هنا جاهز للنسخ واللصق.

> شغّل كل الأوامر من داخل مجلد `damaan/`.

---

## ما يجب أن تجهّزه أنت (لا أحد يستطيع فعله نيابة عنك)

| المطلوب | التكلفة | المدة |
|---|---|---|
| **Apple ID** بالتحقق بخطوتين | مجاني | دقائق |
| **Apple Developer Program** | ‎$99 سنويًا | من ساعات إلى يومين (قد تُطلب هوية) |
| **حساب Expo** على [expo.dev](https://expo.dev) | مجاني | دقائق |

سجّل في برنامج المطورين من: <https://developer.apple.com/programs/enroll/>

> **حساب فردي أم شركة؟** الحساب الفردي يكفي تمامًا لـ«ضَمان»: التطبيق لا يحرّك أموالًا
> ولا يربط حسابات بنكية — هو أرشيف فواتير على الجهاز. (القيود الصارمة التي تتطلب سجلًا
> تجاريًا تخص تطبيقات المحافظ والتحويلات المالية.) الفرق الوحيد: باسم فردي سيظهر اسمك
> الشخصي كناشر للتطبيق، وباسم منظمة يظهر اسم الشركة.

## ١. جهّز الأدوات

```bash
npm install -g eas-cli
eas login
```

## ٢. اربط المشروع بحسابك في Expo

```bash
eas init
```

يضيف هذا `extra.eas.projectId` داخل `app.json` تلقائيًا. **احفظ التغيير في git.**

## ٣. تحقّق أن كل شيء سليم قبل البناء

```bash
npm run verify      # typecheck + lint + 42 اختبارًا
npx expo-doctor     # يجب أن يعطي 21/21
```

لا تكمل إلا إذا نجح الاثنان.

## ٤. عدّل معرّف الحزمة (اختياري لكنه مستحسن)

في `app.json`، غيّر `ios.bundleIdentifier` من `com.damaan.app` إلى نطاق تملكه أنت،
مثل `com.yourname.damaan`. **هذا المعرّف لا يمكن تغييره بعد أول رفع للتطبيق.**

## ٥. ابنِ نسخة الإنتاج

```bash
eas build --platform ios --profile production
```

عند أول مرة ستُسأل:

- **"Generate a new Apple Distribution Certificate?"** → **Yes**
- **"Generate a new Apple Provisioning Profile?"** → **Yes**
- سيطلب تسجيل الدخول بحساب آبل، وسينشئ التطبيق في App Store Connect تلقائيًا إذا لم يكن موجودًا.

البناء يستغرق ١٠–٢٥ دقيقة. تتابعه من الرابط الذي يطبعه الأمر.

## ٦. جهّز صفحة التطبيق في App Store Connect

افتح <https://appstoreconnect.apple.com> → **My Apps** → تطبيقك. املأ:

**المعلومات الأساسية**

| الحقل | القيمة المقترحة |
|---|---|
| الاسم | `ضَمان` |
| العنوان الفرعي | `فواتيرك وضماناتك في مكان واحد` |
| الفئة الأساسية | **Utilities** |
| الفئة الثانوية | **Productivity** |
| اللغة الأساسية | **Arabic** |
| التصنيف العمري | 4+ |

**الوصف** (انسخه كما هو)

```
ضَمان يحفظ فواتير مشترياتك ويتابع لك المهل التي تنساها.

صوّر الفاتورة مرة واحدة، وضَمان يحسب لك ثلاث مهل تبدأ من يوم الشراء:
مهلة الاستبدال، ومهلة الاسترجاع، ومدة الضمان — ويعرضها كعدّاد واضح بالأيام.

• تنبيه قبل انتهاء كل مهلة، لا بعدها
• خطاب مطالبة رسمي بصيغة PDF فيه بياناتك ووصف المشكلة وصورة الفاتورة
• أو رسالة نصية جاهزة ترسلها للمتجر مباشرة
• بحث فوري في كل فواتيرك بالمتجر أو اسم المنتج
• قفل بـ Face ID، ونسخة احتياطية في ملف واحد

كل شيء يبقى على جهازك: بدون حساب، بدون سيرفر، بدون تتبّع، وبدون إنترنت.

ملاحظة: مهل الاسترجاع والاستبدال الافتراضية قابلة للتعديل، لأن سياسة كل متجر تختلف —
راجع ما هو مكتوب على فاتورتك.
```

**الكلمات المفتاحية** (١٠٠ حرف كحد أقصى)

```
فواتير,ضمان,استرجاع,استبدال,warranty,receipt,مشتريات,تذكير,حفظ الفواتير,ضمانات
```

**رابط الدعم**: ضع رابط صفحة أو بريدًا للتواصل (حقل إلزامي).
**سياسة الخصوصية**: انشر محتوى [PRIVACY.md](./PRIVACY.md) على صفحة عامة وضع رابطها (حقل إلزامي).

## ٧. لقطات الشاشة

آبل تطلب لقطات لمقاس **6.9 بوصة** (1320×2868) على الأقل. أسهل طريقة:

```bash
npx expo start --ios
```

شغّل التطبيق على محاكي iPhone 17 Pro Max، أضف ٣–٤ فواتير تجريبية، ثم التقط:

1. **الرئيسية** بعد إضافة عدة فواتير (يظهر شريط الملخص والأقسام الثلاثة)
2. **تفاصيل فاتورة** (تظهر بطاقات المهل الثلاث بشرائط التقدّم)
3. **شاشة المطالبة** مع معاينة الخطاب
4. **نموذج الإضافة** مع صورة فاتورة مرفقة

> لتجميلها بخلفية وعنوان عربي، مرّرها على Canva بمقاس مخصص 1320×2868.

## ٨. أسئلة المراجعة — أجوبتها لهذا التطبيق

| السؤال | الجواب |
|---|---|
| Does your app use encryption? | **No** (مضبوط مسبقًا عبر `ITSAppUsesNonExemptEncryption: false`) |
| Does your app use IDFA? | **No** |
| Sign in required to review? | **No** — التطبيق لا يحتاج حسابًا |
| **App Privacy** | اختر **Data Not Collected** |

> تحذير: إن فعّلت قراءة الفاتورة عبر **خدمة سحابية** (الطريق الثاني في README)، فصورة
> الفاتورة تغادر الجهاز — عندها لا يصح اختيار "Data Not Collected"، ويجب تعديل سياسة
> الخصوصية ونموذج App Privacy. أما التعرّف على الجهاز فلا يغيّر شيئًا.

## ٩. ارفع البناء

```bash
eas submit --platform ios --latest
```

قبل هذا الأمر، املأ الحقول الثلاثة في `eas.json` تحت `submit.production.ios`:
`appleId` و`ascAppId` و`appleTeamId` (تجدها في App Store Connect).

## ١٠. أرسل للمراجعة

في App Store Connect: اختر البناء المرفوع → **Add for Review** → **Submit for Review**.

المراجعة عادةً من ٢٤ إلى ٤٨ ساعة.

## تحديثات لاحقة

**تغيير في الكود فقط (بدون مكتبات أصلية جديدة):** يصل للمستخدمين فورًا بدون مراجعة:

```bash
eas update --branch production --message "وصف التغيير"
```

**تغيير يشمل مكتبة أصلية أو إعدادات `app.json`:** يحتاج بناءً ورفعًا جديدًا:

```bash
eas build --platform ios --profile production
eas submit --platform ios --latest
```

`autoIncrement` مفعّل في `eas.json`، فرقم البناء يزيد تلقائيًا. زِد `version` في
`app.json` يدويًا عند كل إصدار للمستخدمين (مثلًا `1.0.0` ← `1.1.0`).
